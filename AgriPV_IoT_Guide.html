1. Introduction

This guide details the full installation and configuration of an IoT system for the AgriPV project, using:

  • Mosquitto MQTT broker for sensor communication
  • TimescaleDB (built on PostgreSQL) for time-series data
  • Python microservice for data ingestion and processing
Tip: All code blocks have copy buttons. Click them to copy commands directly to your clipboard.
Important Naming Convention: This guide uses snake_case for all database tables, columns, and JSON keys (e.g., raw_sensor_data, sensor_id, raw_value). Ensure consistency throughout to avoid errors.

System Architecture

  • IoT Sensors publish on MQTT topics
  • Mosquitto Broker (port 1883) distributes messages
  • mqtt-processor (Python) inserts data into TimescaleDB (port 5432)

Paste the following Python code:

import os
import json
import time
from datetime import datetime

import paho.mqtt.client as mqtt
import psycopg2


# Configuration from environment variables
MQTT_BROKER = os.getenv("MQTT_BROKER", "mosquitto")
MQTT_PORT = int(os.getenv("MQTT_PORT", "1883"))

DB_HOST = os.getenv("DB_HOST", "timescaledb")
DB_PORT = int(os.getenv("DB_PORT", "*****"))
DB_NAME = os.getenv("DB_NAME", "*****")
DB_USER = os.getenv("DB_USER", "*****")
DB_PASSWORD = os.getenv("DB_PASSWORD", "*****")


def get_db_connection():
    """Create and return a PostgreSQL connection."""
    try:
        conn = psycopg2.connect(
            host=DB_HOST,
            port=DB_PORT,
            dbname=DB_NAME,
            user=DB_USER,
            password=DB_PASSWORD,
        )
        print(f"Connected to database {DB_NAME}", flush=True)
        return conn
    except Exception as exc:
        print(f"Database connection error: {exc}", flush=True)
        return None


def insert_raw_sensor_data(conn, data):
    """
    Insert a raw sensor data point into raw_sensor_data table.

    Expected JSON payload keys (snake_case):
      sensor_id, raw_value, corrected_value, acquisition_time, data_quality, validation_flags
    """
    try:
        cursor = conn.cursor()
        # IMPORTANT: Table and column names must match SQL schema exactly
        query = """
            INSERT INTO raw_sensor_data
                (sensor_id, raw_value, corrected_value,
                 acquisition_time, data_quality,
                 validation_flags, received_time)
            VALUES (%s, %s, %s, %s, %s, %s, NOW());
        """

        # Extract values using snake_case keys
        sensor_id = data.get("sensor_id")
        raw_value = data.get("raw_value")
        corrected_value = data.get("corrected_value")
        acquisition_time = data.get("acquisition_time", datetime.utcnow().isoformat())
        data_quality = data.get("data_quality", "good")
        validation_flags = json.dumps(data.get("validation_flags", {}))

        cursor.execute(
            query,
            (
                sensor_id,
                raw_value,
                corrected_value,
                acquisition_time,
                data_quality,
                validation_flags,
            ),
        )
        conn.commit()
        cursor.close()
        print(f"Inserted sensor data for {sensor_id}", flush=True)
    except Exception as exc:
        print(f"Error inserting sensor data: {exc}", flush=True)
        conn.rollback()


def on_connect(client, userdata, flags, rc):
    """MQTT on_connect callback."""
    if rc == 0:
        print(f"Connected to MQTT broker {MQTT_BROKER}", flush=True)
        client.subscribe("agripv/#")
        print("Subscribed to all agripv/# topics", flush=True)
    else:
        print(f"MQTT connection failed with code {rc}", flush=True)


def on_message(client, userdata, msg):
    """MQTT on_message callback."""
    topic = msg.topic
    try:
        payload = json.loads(msg.payload.decode())
        print(f"Message received on {topic}", flush=True)

        conn = userdata.get("db_conn")
        if conn is None:
            print("No DB connection, ignoring message", flush=True)
            return

        # Currently only handles topics ending in /raw
        # Topics like /heartbeat and /error are received but not processed
        if "/sensors/" in topic and topic.endswith("/raw"):
            insert_raw_sensor_data(conn, payload)

    except json.JSONDecodeError:
        print(f"JSON decode error on topic {topic}", flush=True)
    except Exception as exc:
        print(f"Error handling message on {topic}: {exc}", flush=True)


def main():
    print("Waiting for services to start...", flush=True)
    time.sleep(10)

    db_conn = get_db_connection()
    if not db_conn:
        print("Unable to connect to DB, exiting.", flush=True)
        return

    client = mqtt.Client(userdata={"db_conn": db_conn})
    client.on_connect = on_connect
    client.on_message = on_message

    try:
        client.connect(MQTT_BROKER, MQTT_PORT, keepalive=60)
        print("Microservice started", flush=True)
        client.loop_forever()
    except Exception as exc:
        print(f"MQTT connection error: {exc}", flush=True)
    finally:
        db_conn.close()


if __name__ == "__main__":
    main()

Save with Ctrl+O, Enter, Ctrl+X

Note: The current script only processes messages on topics ending in /raw. Messages on /heartbeat or /error topics will be received but ignored. To handle those, you would need to add additional elif blocks and corresponding database tables.

7.2 Create the complete schema

Copy and paste this full SQL script into the AgriPVDB=# prompt and press Enter:

-- Enable TimescaleDB
CREATE EXTENSION IF NOT EXISTS timescaledb;

-- Relational tables
CREATE TABLE device (
  device_id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  device_name            TEXT,
  device_type            TEXT,
  location               TEXT,
  communication_protocol TEXT,
  hardware_config        JSONB,
  installation_date      TIMESTAMP,
  last_maintenance       TIMESTAMP,
  status                 TEXT,
  battery_level          FLOAT,
  last_heartbeat         TIMESTAMP
);

CREATE TABLE sensor (
  sensor_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  device_id          UUID REFERENCES device(device_id),
  sensor_type        TEXT,
  measurement_unit   TEXT,
  min_range          FLOAT,
  max_range          FLOAT,
  calibration_factor FLOAT,
  calibration_curve  JSONB,
  hardware_status    TEXT,
  last_calibration   TIMESTAMP
);

-- Time-series tables (using snake_case)
CREATE TABLE raw_sensor_data (
  data_id          UUID DEFAULT gen_random_uuid(),
  sensor_id        UUID REFERENCES sensor(sensor_id),
  raw_value        FLOAT,
  corrected_value  FLOAT,
  acquisition_time TIMESTAMP NOT NULL,
  data_quality     TEXT,
  validation_flags JSONB,
  error_codes      TEXT,
  received_time    TIMESTAMP
);

SELECT create_hypertable('raw_sensor_data', 'acquisition_time');

CREATE TABLE hardware_error (
  error_id          UUID DEFAULT gen_random_uuid(),
  device_id         UUID REFERENCES device(device_id),
  sensor_id         UUID REFERENCES sensor(sensor_id),
  error_type        TEXT,
  error_severity    TEXT,
  error_description TEXT,
  error_context     JSONB,
  error_time        TIMESTAMP NOT NULL,
  recovery_action   TEXT,
  resolved_time     TIMESTAMP,
  resolution_status TEXT
);

SELECT create_hypertable('hardware_error', 'error_time');

12. MQTT Topics Organization

Topics follow the pattern: agripv/devices/{device_id}/...

  • agripv/devices/{device_id}/status – Device status
  • agripv/devices/{device_id}/heartbeat – Heartbeat/battery info
  • agripv/devices/{device_id}/sensors/{sensor_id}/raw – Raw sensor data (currently processed)
  • agripv/devices/{device_id}/sensors/{sensor_id}/error – Hardware errors
  • agripv/system/health – System health status

Troubleshooting

Common Mistakes

"Inserted sensor data for None"

  • Cause: JSON keys in your MQTT message don't match what Python expects.
  • Solution: Use snake_case keys: sensor_id, raw_value, corrected_value, etc.

"invalid input syntax for type uuid"

  • Cause: You used a short string like "s1" instead of a valid UUID.
  • Solution: Use uuidgen to create proper UUIDs (format: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx).

"relation 'rawsensordata' does not exist"

  • Cause: Table name mismatch. The SQL uses raw_sensor_data but Python uses rawsensordata.
  • Solution: Ensure your processor.py uses raw_sensor_data (with underscores). Then rebuild: 
    cd ~/agri-db
sudo docker compose up -d --build mqtt-processor

Code changes not taking effect

  • Cause: Docker uses a cached image with old code.
  • Solution: Always rebuild after editing processor.py: 
    cd ~/agri-db
sudo docker compose up -d --build mqtt-processor

Other Issues

Logs not displaying

  • Cause: Python buffering stdout.
  • Solution: Ensure Dockerfile uses python -u and all print() statements have flush=True.

Container restarts in a loop

  • Diagnostic: 
    sudo docker compose logs mqtt-processor --tail 50
  • Possible causes:
    • Database not ready yet (normal on first boot, wait 10-15 seconds)
    • Wrong environment variables in docker-compose.yml
    • Syntax error in processor.py

Complete reset and fresh start

cd ~/agri-db
sudo docker compose down -v
sudo docker compose up -d
# Wait 15 seconds, then run the SQL schema from Section 7.2
